## 0. 전략 — 20시간을 어떻게 쓰나

1. **수직 슬라이스.** 화면 하나에 백+프론트를 묶어 한 사람이 끝까지 만든다. 인수인계 비용 제로.

3. **컷라인 명시.** 모든 Task에 A(시연 필수)/B(있으면 좋음)/C(버림) 등급을 붙였다. 밀리면 **B·C를 버리지 A를 줄이지 않는다.**
4. **시연 역산.** 시연 시나리오(§6)에 나오는 화면만 A등급이다. 나머지는 전부 B 이하.

## 2. DB 스키마 초안

```
users             id(=학번, PK) · email · pw_hash · name · dept · birth · gender
                  · academic_status(재학/휴학/졸업) · is_admin · email_verified
                  · ai_key_enc(암호화, nullable)
clubs             id · name · category · founded_year · purpose · advisor
                  · image · meet_day/time/place · recruit_status · current_gen
                  · status(활동중/보관)
club_members      user_id+club_id(PK) · role(장/부원) · membership(활동중/OB) · gen
join_requests     id · user_id · club_id · status(심사중/승인/거절/취소) · form_answer(json) · created_at
join_forms        club_id(PK) · fields(json) · required(bool)
leave_requests    id · user_id · club_id · status · created_at   ← 7일 자동승인
club_applications id · applicant_id · name · category · founded_year · purpose
                  · advisor · status · reject_reason
posts             id · club_id · author_id · title · body · photos(json) · activity_date
                  · tags(json) · is_public(기본 false) · created_at
likes             user_id+post_id(PK)
email_tokens      token · user_id · expires_at
```

- 학번을 PK로 쓴다 (기획 §4.1). 이메일 도메인 2종은 컬럼 하나로 흡수.
- 7일 자동탈퇴는 **스케줄러 없이** 처리한다: 동아리장이 탈퇴요청 목록을 열 때 + 해당 유저 로그인 시 만료 건을 승인 처리. `# ponytail: 폴링 없음, 조회 시점 처리`

## 5. 병렬 작업 규칙 (충돌 방지)

- T0 이후 `models.py`는 **추가만** 허용. 수정 필요하면 PM 합의.
- 라우터는 파일 단위로 분담이 갈린다 — 같은 파일을 두 명이 만질 일 없음.
- 프론트 view도 화면 단위로 갈린다. 공용 컴포넌트가 필요하면 만든 사람이 소유.
- 머지 순서로 충돌을 줄인다: 작은 PR 자주. 반나절 넘게 브랜치에 쌓아두지 않는다.
