# 실제 동아리 데이터 크롤링 — 설계

지어낸 데모 동아리 8개를 **명지전문대학이 실제로 등록한 동아리 25개**로 교체한다.

출처: <https://www.mjc.ac.kr/ibuilder.do?menu_idx=155> (생활서비스 › 학생활동 › 동아리)

---

## 1. 왜

지금 시드의 동아리는 전부 지어낸 것이다. 서비스가 "우리 학교 동아리를 찾는 곳"인데 목록에 우리 학교 동아리가 없다. 실제 데이터가 들어가야 화면이 쓸 만한지도 제대로 판단된다 — 이름 길이, 분야 분포, 창립년도 폭이 전부 달라진다.

## 2. 원본이 가진 것

정적 HTML 표 하나(`table.tbl_type01`). JS 렌더링도 페이지네이션도 없고, `robots.txt`는 `Allow: /`다.

| 항목 | 값 |
|---|---|
| 동아리 수 | **25** |
| 컬럼 | 분야 · 동아리명 · 창립년도 · 목적 · 주요사업 |
| 분야 분포 | 봉사 2 · 학술 13 · 체육 7 · 종교 3 |
| 창립년도 | 1974 ~ 2018 |

분야 칸은 `rowspan`(최대 13)으로 묶여 있고 `봉사(2개)`처럼 개수가 붙어 있다.

## 3. 결정 사항

### 3.1 분류는 원본을 따른다 — `종교`를 추가한다

원본의 4분류를 그대로 쓴다. 우리가 임의로 재분류하지 않는다. 학교 공식 분류와 일치해야 "실제 데이터"라고 말할 수 있고, 분류 근거를 방어할 필요도 없다.

| 원본 | 우리 라벨 |
|---|---|
| 학술 | `학술·전공` |
| 체육 | `체육` |
| 봉사 | `봉사` |
| 종교 | **`종교`** ← 신규 |

`공연·예술` · `취미·교양`은 열거값에 남겨둔다. 새로 개설 신청하는 동아리가 쓸 수 있다.

원본의 "학술 13개"에는 우리 눈에 공연·예술로 보이는 동아리(블랙비트·때깔·궁상각치우 등)가 섞여 있다. **그래도 옮기지 않는다.** 학교가 학술로 등록한 것을 우리가 재분류하면 그 순간 출처가 우리 판단이 된다.

### 3.2 동아리장은 비워둔다

크롤링으로 들어온 동아리에는 운영 주체가 없다. `leader` 를 `null` 로 둔다. 계약(`api.md` §3)이 이미 `leader: null` 을 허용하고, 관리자 강제 지정 API(`PATCH /api/admin/clubs/{id}` 의 `leader_id`)도 있다.

**"학교가 등록한 동아리 목록은 있고, 운영 주체는 아직 이 서비스에 들어오지 않았다"** 는 상태를 그대로 표현한다. 실제 동아리장이 가입하면 관리자가 지정한다.

### 3.3 모집 상태는 `모집마감`

동아리장이 없으니 **신청해도 승인해줄 사람이 없다.** 모집중으로 표시하면 신입생이 신청하고 답을 영영 못 받는다. 동아리장이 들어와 본인이 모집중으로 바꾸는 것이 맞다.

### 3.4 원본에 없는 값

| 필드 | 값 | 근거 |
|---|---|---|
| `advisor` | `""` | 원본에 없음 |
| `meet_day` · `meet_time` · `meet_place` | `null` | 원본에 없음. 화면이 "미정"으로 처리한다 |
| `image` | `null` | 분야 그라데이션 폴백이 이미 동작한다 |
| `current_gen` | `null` | 비면 화면에 표시하지 않는다 |
| `주요사업` | `purpose` 에 이어붙임 | 컬럼을 새로 만들 만한 값이 아니다. `purpose` 는 줄바꿈 포함 원문이고 프론트가 문단으로 나눈다 |

`purpose` 형식:

```
사진촬영, 작품연구

주요사업: 작품전시회 개최
```

### 3.5 활동 글은 실제 동아리로 재배치한다

데모 동아리를 지우면 거기 달린 활동 글 18건이 함께 사라진다. 그러면 메인 캐러셀과 모든 타임라인이 빈다 — "활동 기록이 주인공"인 서비스에서 기록이 0건이 된다.

**글 내용과 성격이 맞는 실제 동아리로 옮긴다.** 자연스러운 자리가 없는 글은 버린다.

- 출사·암실·전시 → **고리사진부**(사진촬영, 작품연구)
- 리그 경기·순연 → **축구부**(축구를 통한 체력증진)
- 정기공연·오디션 → **노래창고**(정기발표회)
- 대본 리딩·무대 철수 → **희비**(정기공연)
- 멘토링·연탄 나눔 → **T.M.I.M**(봉사 활동)
- 대회 예선·본선 → **e-sports**(각종대회 참가 및 개최)

**받아들임 기준: 최소 6개 동아리에 공개 글이 붙어야 한다.** 메인 캐러셀이 동아리당 1건만 뽑으므로(`api.md` §9-4), 6개 미만이면 캐러셀이 허전해진다.

글 본문은 여전히 지어낸 데모 텍스트다. `seed.py` 상단 주석에 **"동아리 정보는 학교 공개 자료, 활동 글은 데모용 창작"** 임을 명시한다.

## 4. 크롤러

`backend/crawl_clubs.py` — `check_mail.py` 와 같은 위치·같은 성격의 **손으로 돌리는 스크립트**다. `seed.py` 나 앱 실행 경로에 붙이지 않는다.

```bash
cd backend && uv run python crawl_clubs.py            # 긁어서 JSON 갱신
cd backend && uv run python crawl_clubs.py --dry-run  # 화면에만 출력
```

- HTTP: 기존 의존성 `httpx`
- 파싱: **`beautifulsoup4` 를 dev 그룹에 추가.** 도커는 `--no-dev` 로 빌드하므로 운영 이미지에 안 들어간다
- `rowspan` 이월 처리와 `봉사(2개)` → `봉사` 정리를 크롤러가 한다

**실패하면 JSON을 건드리지 않는다.** 표를 못 찾거나, 헤더가 예상과 다르거나, 행이 20개 미만이면 오류로 끝낸다. 학교가 페이지를 개편했는데 조용히 빈 파일을 쓰는 것이 최악이다.

## 5. 산출물 — `backend/data/clubs.json`

**git에 커밋되는 원본이다.** DB는 언제든 버려도 되는 사본이다.

이 프로젝트는 마이그레이션 도구를 쓰지 않는다(구현계획 §7). 스키마가 바뀌면 `docker compose down -v` 로 DB를 통째로 날린다. 데이터를 DB에만 두면 컬럼 하나 추가할 때마다 사라지고, 손으로 고친 내용도 함께 날아간다.

```
학교 사이트 ──(수동 1회)──▶ clubs.json ──(seed 실행)──▶ DB
                            ↑ git · 여기가 원본        ↑ 언제든 재생성
```

```jsonc
{
  "source": "https://www.mjc.ac.kr/ibuilder.do?menu_idx=155",
  "crawled_at": "2026-08-06",
  "clubs": [
    {
      "name": "고리사진부",
      "category": "학술·전공",     // 우리 열거값
      "source_category": "학술",   // 원본 라벨 — 왜 이 분류인지 추적용
      "founded_year": 1979,
      "purpose": "사진촬영, 작품연구",
      "main_activities": "작품전시회 개최"
    }
  ]
}
```

`seed.py` 는 이 파일만 읽는다. 네트워크를 타지 않으므로 시연 중 학교 서버가 느려도 영향이 없고, CI 테스트도 외부 사이트를 치지 않는다.

## 6. `종교` 추가로 함께 바뀌는 것

분류가 하나 늘면 여러 곳이 따라온다. **`[계약]` PR이다.**

| 파일 | 무엇을 |
|---|---|
| `backend/app/enums.py` | `CATEGORIES` 에 `종교` 추가 |
| `docs/api.md` §0.2 | 열거값 갱신 (계약) |
| `frontend/src/assets/theme.css` | 카테고리 색 1쌍 추가 (라이트·다크) |
| `frontend/src/components/ClubCategory.js` | 그라데이션·이모지 매핑 추가 |
| `docs/specs/…프론트엔드-디자인-기획.md` §2 | 카테고리 5색 → 6색 |

개설 신청 폼·아카이브 파셋은 `enums` 를 따라가는지 확인만 한다.

**`GET /api/stats` 의 `categories` 를 함께 고친다.** 지금은 열거값 개수(`len(CATEGORIES)`)를 돌려준다. 열거값이 6개가 되면 메인 브랜드 섹션이 "분야 6" 이라고 표시하는데, 아카이브에는 동아리가 있는 분야가 4개만 보인다. **실제 동아리가 있는 분야 수**를 세도록 바꾼다. 지표는 열거값 개수가 아니라 사용자가 화면에서 셀 수 있는 값이어야 한다.

## 7. 검증

1. `uv run python crawl_clubs.py --dry-run` → 25개, 분야 분포 2/13/7/3 일치
2. `clubs.json` 육안 확인 — 이름 깨짐·`(N개)` 잔여물 없음
3. `uv run python seed.py --reset` → 동아리 25개 주입
4. `GET /api/clubs` 25건 · `GET /api/stats` 의 `categories` 갱신
5. 브라우저 — 아카이브에 `종교` 그룹이 색과 함께 뜨는지, 동아리 상세에서 지도교수·정기모임이 "미정"으로 처리되는지, 동아리장 없는 상세가 깨지지 않는지
6. **캐러셀에 6개 이상**의 서로 다른 동아리가 뜨는지
7. `pytest -q` · `ruff check .` · `npm run build`

## 8. 이번 범위에서 뺀 것

| 뺀 것 | 이유 |
|---|---|
| 자동·주기 크롤링 | 25개가 자주 바뀌지 않는다. 필요할 때 손으로 돌린다 |
| 관리자 화면의 '동기화' 버튼 | 서버가 외부 사이트를 긁는 구조(실패·중복·권한)가 따라붙는다 |
| 동아리 사진 수집 | 원본에 없다. 저작권 확인이 따로 필요하다 |
| 원본 분류를 우리 5분류로 재해석 | 3.1 참고 — 출처가 우리 판단이 되어버린다 |
| 지도교수 이름 수집 | 원본에 없고, 개인정보라 별도 확인이 필요하다 |
