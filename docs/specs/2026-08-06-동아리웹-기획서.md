# 명지전문대학 동아리 웹사이트 — 기획서

2026학년도 RISE사업단 AI 해커톤 경진대회 / 주제 2

---

## 1. 한 줄 정의

명지전문대학 학생이 동아리를 찾고 가입할 수 있고, 동아리장은 **사진과 메모만 올리면 명지전문대학 AI가 활동 글 초안을 써주는** 동아리 활동 기록·홍보 웹사이트.

## 2. 왜 만드는가

동아리 홈페이지는 만들 때는 열심히 만들지만 **두 달이면 죽는다.** 관심이 없어서가 아니라 글 쓰기가 귀찮아서다. 사진은 단톡방에 100장 쌓여 있는데 홈페이지의 마지막 글은 3월이다.

그래서 이 서비스의 중심 기능은 게시판이 아니라 **기록의 진입 장벽을 없애는 것**이다. 동아리장이 행사 끝나고 사진 몇 장과 한 줄 메모를 올리면, AI가 활동 글 초안을 만들어 편집창에 채워 넣는다. 동아리장은 고치고 게시만 하면 된다.

신입생 입장에서는 "우리 동아리는 열정적입니다" 같은 소개글 대신 **지난주에 실제로 뭘 했는지**를 보고 고를 수 있게 된다.

## 3. 사용자와 권한

### 3.1 세 개의 축을 분리한다

초안에서 "재학중, 졸업, 휴학중, 동아리장 4개의 역할"로 묶여 있던 것을 세 축으로 나눈다. 서로 다른 성격의 값이 한 열거에 섞여 있었기 때문이다.

| 축 | 값 | 붙는 대상 | 누가 바꾸나 |
|---|---|---|---|
| **학적 상태** | 재학 / 휴학 / 졸업 | 사람 (계정에 1개) | 본인 |
| **동아리 멤버십** | 활동중 / OB | 사람 × 동아리 (동아리마다) | 학적 상태에 따라 자동 |
| **동아리 직책** | 동아리장 / 부원 | 사람 × 동아리 (동아리마다) | 위임 또는 관리자 |
| **기수** | 숫자 (12기 등) | 사람 × 동아리 (동아리마다) | 동아리장 |
| **시스템 권한** | 사이트 관리자 / 일반 | 사람 | 관리자 |

한 사람이 동아리 3개에 속하면 학적은 하나지만 직책·멤버십·기수는 각각 3개다. 동아리 A에서는 12기 부원이고 B에서는 3기 동아리장일 수 있다.

## 4. 계정

### 4.1 가입

- 이메일은 `학번@mjc.ac.kr` 또는 `학번@on.mjc.ac.kr` 만 허용한다.
- 입력 항목: 이메일, 비밀번호, 학번, 이름, 학과, 생년월일, 성별
- **학번이 계정의 고유 식별자**다. 숫자로만 이루어진다. 이메일 도메인이 두 개이므로, 같은 학번으로 두 도메인을 각각 가입하는 것은 허용하지 않는다. 학번이 이미 있으면 가입이 막힌다.
- 가입 직후 상태는 **미인증**. 인증 메일의 링크를 눌러야 활성화된다.

### 4.2 로그인

이메일 + 비밀번호. 인증 전 계정으로 로그인하면 "인증 메일을 확인해주세요 / 다시 보내기" 안내를 띄운다.

### 4.3 내 정보에서 바꿀 수 있는 것

| 항목 | 수정 | 비고 |
|---|:--:|---|
| 비밀번호 | ○ | |
| 학과 | ○ | 전과 반영 |
| 학적 상태 | ○ | 휴학·졸업 반영 |
| **AI API 키** | ○ | 등록 / 교체 / 삭제. 아래 4.5 참고 |
| 이름 · 학번 · 생년월일 · 성별 · 이메일 | × | 잠금. 변경이 필요하면 관리자 문의 |

초안의 "개인정보는 비밀번호만 수정 가능"에서 **학과와 학적 상태를 열었다.** 전과와 휴학은 실제로 일어나는 일이고, 유저가 못 고치면 관리자가 전부 대신 처리해야 하기 때문이다.

**학적을 '졸업'으로 바꿀 때 예외가 있다.** 동아리장을 맡고 있는 동아리가 하나라도 있으면 졸업 전환을 막고, 위임 또는 관리자 교체 요청을 먼저 하도록 안내한다. 동아리장이 OB가 되어 권한을 잃으면 그 동아리 전체가 마비되기 때문이다.

### 4.4 내 정보 페이지에 보이는 것

- 내가 가입된 동아리 목록 (동아리별 **기수** · 직책 · 멤버십 상태 함께)
- **내 신청 현황** — 가입 신청 / 개설 신청 / 탈퇴 요청의 상태(심사중·승인·거절)를 한 곳에서 본다. 심사중인 신청은 **취소**할 수 있다.
- **AI API 키 등록란**

### 4.5 AI API 키 등록

AI 초안 기능은 **사용자 개인이 발급받은 명지전문대학 AI Gateway 키**로 동작한다. 서비스가 공용 키를 쥐고 대신 호출하지 않는다.

**발급은 사용자가 직접 한다.** 명지전문대학 AI 문서(`docs.mindlogic.ai`)에서 로그인 후 API Gateway 메뉴에서 키를 생성한다. 내 정보 페이지에는 이 발급 절차 안내와 문서 링크를 함께 둔다.

**보관 규칙** — 남의 API 키를 우리 DB에 넣는 일이므로 규칙을 명시한다.

| 규칙 | 내용 |
|---|---|
| 평문 저장 금지 | 서버에서 암호화해 저장한다 |
| 해시 아님 | 실제로 호출에 써야 하므로 복호화 가능한 방식이어야 한다. 비밀번호와 다르다 |
| 재조회 불가 | 저장 후에는 화면에 마스킹된 형태(`****abcd`)만 보인다. 발급처도 재조회를 지원하지 않는다 |
| 언제든 교체·삭제 | 노출이 의심되면 사용자가 즉시 지우고 새 키를 넣는다 |
| 등록 시 유효성 확인 | 저장 전에 게이트웨이의 모델 목록 조회로 키가 살아 있는지 한 번 확인한다. 글 쓰다가 실패하는 상황을 막는다 |
| 다른 사람에게 노출 안 됨 | 관리자도 남의 키 값을 볼 수 없다. 등록 여부만 확인된다 |

**키가 없어도 서비스는 정상 동작한다.** 활동 글 작성 화면은 그대로 열리고 'AI 초안 생성' 버튼만 비활성화되며, 옆에 "내 정보에서 AI API 키를 등록하면 사용할 수 있어요" 안내와 링크가 붙는다. AI는 글쓰기를 **거드는** 기능이지 필수 경로가 아니다.

키는 사람에게 붙는다. 동아리장이 바뀌면 새 동아리장 본인의 키로 동작한다.

## 5. 동아리

### 5.1 동아리가 가진 정보

| 항목 | 누가 정하나 | 비고 |
|---|---|---|
| 이름 | 개설 신청자 | |
| 카테고리 | 개설 신청자 | 학술·전공 / 공연·예술 / 체육 / 봉사 / 취미·교양 |
| 창립년도 | 개설 신청자 | |
| 목적·소개 | 개설 신청자 → 동아리장이 수정 | |
| 지도교수명 | 개설 신청자 | |
| 대표 이미지 | 동아리장 | 없으면 기본 이미지 |
| 정기 모임 요일·시간·장소 | 동아리장 | |
| 모집 상태 | 동아리장 | 모집중 / 모집마감 / 상시모집 |
| **현재 기수** | 동아리장 | 지금 모집 중인 기수. 가입 승인 시 이 값이 부여된다 |
| 운영 상태 | 관리자 | 활동중 / 보관 |

정원은 두지 않는다. 동아리장이 가입 승인으로 조절하거나 모집 상태를 '마감'으로 바꾸면 충분하다.

**카테고리와 모집 상태는 초안에 없던 항목이다.** 동아리가 수십 개인데 목록만 주면 찾을 수 없어서 추가했다.

### 5.2 개설 신청

개설 신청 하나로 **신규 창설과 기존 동아리 등록**을 모두 처리한다. 이미 존재하는 밴드부·축구부도 이 사이트에 처음 들어올 때는 개설 신청을 거쳐야 하므로, 창립년도를 받는 것은 모순이 아니라 **수동 마이그레이션을 위한 필수 필드**다. 신규 창설이면 올해를 적으면 된다.

- 신청자가 곧 동아리장이 된다.
- 관리자가 승인하면 개설되고, 거절하면 **사유와 함께** 이메일로 통보한다.
- 심사중인 신청은 신청자가 취소할 수 있다.

### 5.3 가입

1. 학생이 동아리 상세 페이지에서 가입 신청
2. 동아리장이 가입폼을 만들어 두었다면 폼을 작성한다
   - 동아리장은 가입폼을 만들고 고치고 지울 수 있다
   - **폼 작성을 필수로 할지 선택으로 할지**도 동아리장이 정한다
3. 동아리장이 신청자 목록에서 승인 또는 거절
4. 승인되면 동아리의 **현재 기수**가 자동으로 부여된다
5. 결과는 이메일과 '내 신청 현황'에 반영

동아리장에게 보이는 신청자 정보는 **이름 · 학과 · 학년**과 가입폼 답변이다.

> 초안에서는 이름·생년월일·학과·학번·성별을 모두 보여줬다. 가입 심사에 성별과 생년월일이 왜 필요한지 설명할 수 없고, 학번 전체는 이메일 주소와 같아 개인 식별 정보가 된다. 최소 수집·최소 노출 원칙에 따라 학번은 앞 두 자리에서 도출한 **학년**으로만 표시한다.

한 사람이 여러 동아리에 가입할 수 있다. 같은 동아리에 중복 신청은 막고, 거절된 뒤에는 다시 신청할 수 있다.

### 5.3.1 기수

기수는 **동아리마다 따로 붙는 값**이다. 같은 사람이 A 동아리 12기, B 동아리 3기일 수 있다.

- 동아리 설정의 '현재 기수'가 가입 승인 시 자동 부여된다. 동아리장이 매번 입력할 필요가 없다.
- **부원 관리 화면**에서 동아리장이 개별 부원의 기수를 고칠 수 있다. 마이그레이션으로 들어온 기존 동아리는 승인 시 전부 같은 기수가 되므로, 실제 기수로 한 번 정리해야 한다.
- 새 학기에 동아리장이 '현재 기수'를 올리면 그 뒤 승인된 신입만 새 기수를 받는다. 기존 부원의 기수는 그대로다.
- 기수를 쓰지 않는 동아리는 비워둘 수 있다. 비어 있으면 화면에 표시하지 않는다.
- 부원 본인은 자기 기수를 바꿀 수 없다. 기수는 동아리가 부여하는 값이다.

기수는 부원 목록 정렬과 그룹 표시에 쓰인다. OB가 늘어날수록 "몇 기까지가 활동중인지" 파악에 필요해진다.

### 5.4 탈퇴

1. 부원이 탈퇴 요청
2. 동아리장이 수락하면 탈퇴 완료
3. **7일 동안 동아리장이 처리하지 않으면 자동으로 탈퇴 처리된다**

> 초안대로 동아리장 승인만 있으면, 동아리장이 잠수탔을 때 부원이 영원히 나가지 못한다. 자동 탈퇴는 동아리장에게 인수인계 시간을 주면서도 사용자가 갇히지 않게 하는 장치다.

동아리장 본인은 위임하기 전까지 탈퇴할 수 없다.

### 5.5 동아리장 위임과 공석

- 동아리장은 같은 동아리의 **활동중인 부원**에게 위임할 수 있다. 위임하면 본인은 부원이 된다.
- 동아리장이 잠수·졸업 등으로 사라진 경우, 부원이 관리자에게 신고하면 **관리자가 다른 부원을 동아리장으로 강제 지정**한다. 초안의 "관리자는 모든 것을 CRUD한다"의 구체적 적용이다.

### 5.6 해산

동아리를 삭제하지 않고 **보관 상태**로 바꾼다. 과거 활동 기록은 계속 열람할 수 있고 신규 가입만 막힌다. 나중에 부활할 수도 있다. 몇 년치 활동 기록이 통째로 사라지는 것이 더 큰 손실이다.

## 6. 활동 글

### 6.1 구성

| 항목 | 채우는 방법 |
|---|---|
| 동아리명 | 자동 |
| 작성자 | 자동 (동아리장) |
| 제목 | AI 초안 또는 직접 |
| 본문 | AI 초안 또는 직접 |
| 사진 | 업로드 |
| 활동 날짜 | 직접 |
| 태그 / 활동 유형 | AI 초안 또는 직접 |
| 공개 범위 | **기본 비공개**, 동아리장이 공개로 변경 가능 |

**작성 권한은 동아리장만** 가진다. 권한 구조가 단순해지고 글 품질도 관리된다.

**공개 기본값을 비공개로 둔 이유:** 활동 사진에는 학생 얼굴이 들어간다. 공개가 기본이면 실수로 초상권 사고가 난다. 공개는 동아리장이 의식적으로 체크하는 행위여야 한다.

### 6.2 열람

- 공개 글: 누구나 (비로그인 포함)
- 비공개 글: 해당 동아리 소속(부원·OB·동아리장)과 관리자만. 목록에도 제목이 뜨지 않는다.
- 좋아요: 로그인한 사용자만, 1인 1회

댓글은 두지 않는다. 신고·삭제·분쟁 처리 구조가 필요해지는데, 이 서비스의 목적은 토론이 아니라 기록이다.

## 7. AI 활동 글 초안 — 핵심 기능

### 7.0 어떤 AI를 쓰는가

**명지전문대학 AI Gateway** (`docs.mindlogic.ai`)를 쓴다. OpenAI·Anthropic·Gemini 등 여러 제공사의 모델을 하나의 키와 Base URL로 묶어주는 게이트웨이다.

- Base URL: `https://factchat-cloud.mindlogic.ai/v1/gateway`
- 인증: `Authorization: Bearer <키>` 또는 `x-api-key: <키>`
- 키는 **사용자 개인이 발급**해서 내 정보에 등록한다 (4.5)

**2026-08-06 실제 호출로 확인한 것** (스모크 테스트 5종 전부 통과):

| 항목 | 결과 |
|---|---|
| `GET /models/` | 200 · 모델 80종 (`claude-sonnet-5`, `gpt-5.6-luna`, `gemini-3.6-flash` 등) |
| 인증 헤더 | `Authorization: Bearer` · `x-api-key` **둘 다** 동작 |
| `POST /chat/completions/` | 200 · 한국어 생성 정상 |
| **이미지 입력(비전)** | **200 · 지원됨.** 좌우 색이 다른 테스트 이미지를 정확히 판별 |
| `POST /claude/v1/messages/` | 200 · Anthropic 네이티브 경로도 동작 |

> ⚠️ **User-Agent 를 반드시 지정할 것.** 기본 UA(`Python-urllib/…`, `python-httpx/…`)로 호출하면
> Cloudflare 가 **403 (error code 1010)** 으로 차단한다. 키 문제로 오인하기 쉬우니 주의.
> 브라우저형 UA 를 헤더에 넣으면 정상 동작한다.

외부 상용 API를 따로 결제하지 않고 **학교가 제공하는 인프라를 그대로 쓴다**는 점, 그리고 비용이 서비스 운영자 한 곳에 몰리지 않는다는 점이 이 선택의 이유다.

### 7.1 무엇을 하는가

동아리장이 활동 글 작성 화면에서 아래 재료를 올리면, AI가 **제목·본문·태그 초안**을 만들어 편집창에 채워 넣는다.

| 입력 | 설명 |
|---|---|
| 사진 | 여러 장. 행사 현장 사진 |
| 메모 | 한두 줄. "10/12 성북동 출사, 12명 참여, 필름 현상은 다음 주" |
| PDF | 학생지원팀에 제출하는 **활동 결과보고서** |

세 가지를 다 넣을 필요는 없다. 메모만 있어도 되고, 결과보고서만 있어도 된다.

**PDF는 서버가 먼저 텍스트로 바꾼다.** 게이트웨이에는 파일 업로드 엔드포인트가 없으므로, 우리 서버가 결과보고서에서 글자를 뽑아 프롬프트에 담아 보낸다. 스캔본처럼 글자가 안 뽑히는 PDF는 "내용을 읽을 수 없습니다. 메모로 적어주세요"라고 안내한다.

### 7.2 환각을 막는 규칙 — 이 기능의 핵심 설계

**사진만 있고 메모가 없으면 초안을 만들지 않는다.** 대신 "무슨 활동이었는지 한 줄만 적어주세요"라고 요청한다.

사진만으로 글을 쓰게 하면 AI는 "즐거운 시간을 보냈습니다", "뜻깊은 자리였습니다" 같은 문장을 지어낸다. 아무 동아리에나 붙는 문장이라 읽는 사람에게 정보가 없고, 사실이 아닐 수도 있다.

그래서 역할을 나눈다.

- **메모와 PDF가 사실을 제공한다** — 날짜, 장소, 인원, 무엇을 했는지
- **사진은 그 사실을 구체화하는 데만 쓴다** — "12명 참여"를 "12명이 필름 카메라를 들고" 정도로

메모에 없는 사실은 사진만 보고 쓰지 않는다. 이 원칙 하나가 결과물의 신뢰도를 가른다.

### 7.3 사람이 최종 책임을 진다

- AI는 **초안까지만** 만든다. 자동 게시는 없다.
- 초안은 편집창에 채워져 나오고, 동아리장이 읽고 고쳐서 게시한다.
- 다시 생성 버튼은 두지 않는다. 마음에 안 들면 그 자리에서 직접 고치는 편이 빠르다.
- **게시된 글에 'AI 작성' 배지는 붙이지 않는다.** 사람이 검수하고 고쳐서 자기 이름으로 게시한 글이므로 저자는 사람이다. AI 표시는 작성 화면 안에서만 보인다.

### 7.4 이 기능이 실패하는 지점

기획 단계에서 미리 인정해 둔다.

- 메모가 부실하면 초안도 부실하다. AI가 없는 정보를 만들어내지 않기 때문이다. 이건 버그가 아니라 의도된 동작이다.
- 결과보고서 PDF의 서식이 동아리마다 다르면 추출 품질이 흔들린다. 스캔본은 아예 못 읽는다.
- 사진이 어둡거나 인물 위주면 활동 내용을 알아보기 어렵다.
- ~~게이트웨이가 이미지 입력을 지원하지 않을 수 있다~~ → **2026-08-06 확인 결과 지원됨(7.0).** 7.2의 "사진으로 구체화"를 그대로 구현한다. 설계를 사진에 의존하지 않게 짠 원칙은 그대로 유지한다 — 메모 없이 사진만으로는 여전히 초안을 만들지 않는다.
- 개인 키의 사용량 한도는 문서에 명시돼 있지 않다. 한도를 넘기면 그 사용자만 초안 생성이 실패하고, 다른 사용자와 서비스 전체는 영향받지 않는다.

## 9. 개인정보와 안전에 대한 원칙

1. **최소 노출** — 동아리장에게 보이는 신청자 정보는 이름·학과·학년. 성별·생년월일·학번 전체는 보이지 않는다.
2. **기본 비공개** — 활동 글은 기본이 비공개다. 공개는 사람이 의식적으로 선택한다.
3. **탈출구 보장** — 탈퇴는 7일 후 자동 처리된다. 승인권자가 사라져도 사용자가 갇히지 않는다.
4. **책임의 소재** — AI는 초안만 만든다. 게시된 글의 저자는 사람이고 책임도 사람에게 있다.
5. **학교 구성원 확인** — 학교 이메일 도메인 + 인증 메일. 외부인은 계정을 만들 수 없다.
6. **맡긴 자격증명은 돌려주지 않는다** — AI API 키는 암호화 저장하고, 저장 후에는 본인에게도 관리자에게도 값을 보여주지 않는다. 지우고 새로 넣는 것만 가능하다.
7. **AI 사용은 각자의 키로** — 서비스가 공용 키로 대신 호출하지 않는다. 누가 얼마나 썼는지가 발급처에서 개인별로 남고, 한 사람의 한도 초과가 다른 사람에게 번지지 않는다.

## 10. 이번 범위에서 뺀 것

기획에서 **의도적으로 제외했고**, 왜 뺐는지 함께 적는다.

| 뺀 것 | 이유 |
|---|---|
| 댓글 | 신고·삭제·분쟁 처리 구조가 따라붙는다. 이 서비스는 토론이 아니라 기록이 목적이다 |
| 동아리 정원 | 가입 승인과 모집 상태로 충분히 조절된다 |
| 부동아리장·총무 등 임원 직책 | 관리자 강제 교체로 공석 문제가 해결되므로 역할을 늘릴 이유가 없다 |
| 사이트 내 알림함 | 이메일 + '내 신청 현황'으로 같은 목적을 달성한다 |
| AI 초안 다시 생성 / 문체 선택 | 직접 고치는 것이 더 빠르다 |
| 공용 AI 키 (관리자가 넣어두는 방식) | 비용과 남용 책임이 한 곳에 몰린다. 키가 없으면 AI 버튼만 비활성화되고 나머지는 다 돌아간다 |
| 부원 본인의 기수 수정 | 기수는 동아리가 부여하는 값이다 |
| 동아리 간 메시지·쪽지 | 학교 이메일과 단톡방이 이미 하고 있다 |

| 4 | 동아리장 공석 대책 없음 | 관리자 강제 교체 | 동아리 전체가 마비된다 |

| 8 | 신청자 정보 5종 노출 | 이름·학과·학년만 | 심사에 필요 없는 정보는 보지 않는다 |
| 9 | 이메일 인증 절차 없음 | 인증 메일 발송 | 남의 학번으로 가입할 수 있었다 |
| 10 | 분류 체계 없음 | 카테고리 5종 + 모집 상태 | 목록만으로는 찾을 수 없다 |
| 11 | 동아리 해산 절차 없음 | 보관 상태로 전환 | 활동 기록이 통째로 사라지면 안 된다 |
| 12 | 개설 신청 결과 통보 없음 | 사유와 함께 이메일 통보 | 왜 거절됐는지 알아야 다시 신청한다 |
| 13 | 활동 글 공개 기본값 미정 | 기본 비공개 | 사진에 학생 얼굴이 들어간다 |
| 14 | 반응 기능 없음 | 좋아요 (로그인 사용자) | 인기 동아리 파악에 쓰인다 |
| 15 | AI 제공자 미정 | 명지전문대학 AI Gateway, **개인 키** 등록 방식 | 학교 인프라를 쓰고, 비용과 사용량이 개인별로 분리된다 |
| 16 | 기수 개념 없음 | 동아리별 기수, 가입 승인 시 자동 부여 | 동아리 운영의 기본 단위이고, OB가 쌓일수록 필요해진다 |
