# MJC Club Archive

**명지전문대학 동아리 아카이브** — 동아리를 찾고 가입할 수 있고, 동아리장은 **사진과 메모만 올리면 학교 AI가 활동 글 초안을 써주는** 동아리 활동 기록·홍보 웹사이트.

2026학년도 RISE사업단 AI 해커톤 경진대회 · 주제 2 (학업·활동·대학생활 도움)

---

## 왜 만드는가

동아리 홈페이지는 만들 때는 열심히 만들지만 **두 달이면 죽는다.** 관심이 없어서가 아니라 글 쓰기가 귀찮아서다. 사진은 단톡방에 100장 쌓여 있는데 홈페이지의 마지막 글은 3월이다.

그래서 이 서비스의 중심은 게시판이 아니라 **기록의 진입 장벽을 없애는 것**이다. 동아리장이 행사 끝나고 사진 몇 장과 한 줄 메모를 올리면 AI가 초안을 만들어 편집창에 채워 넣는다. 동아리장은 고치고 게시만 하면 된다.

신입생 입장에서는 "우리 동아리는 열정적입니다" 같은 소개글 대신 **지난주에 실제로 뭘 했는지**를 보고 고를 수 있게 된다.

## 핵심 기능

| | |
|---|---|
| **AI 활동 글 초안** | 메모·사진·활동 결과보고서(PDF)를 넣으면 제목·본문·태그 초안이 나온다. 학교가 제공하는 AI Gateway를 **사용자 개인 키**로 호출한다 |
| **활동 기록 중심 탐색** | 메인은 공개된 활동 글이 곡선 캐러셀로 흐르고, 동아리 상세는 타임라인이 주인공이다 |
| **동아리 운영 흐름** | 가입 신청·승인 시 기수 자동 부여, 개설 신청, 부원·탈퇴 관리, 동아리장 위임까지 |

## 시스템 구성

![시스템 구성도](docs/assets/architecture.svg)

프론트는 `docs/api.md` 하나만 보고 개발한다. 백엔드가 아직 없으면 명세대로 mock을 만들어 진행하고, 붙일 때 mock만 제거한다. 이게 세 명이 병렬로 달린 방법이다.

**AI 키는 서비스가 쥐지 않는다.** 사용자가 직접 발급해 '내 정보'에 등록하고, 서버는 Fernet으로 암호화해 보관한다. 저장 후에는 본인에게도 관리자에게도 값을 보여주지 않는다. 누가 얼마나 썼는지가 발급처에서 개인별로 남고, 한 사람의 한도 초과가 다른 사람에게 번지지 않는다.

## 화면 구조

![화면 구조도](docs/assets/screens.svg)

권한은 네 축으로 분리했다 — **학적 상태**(재학/휴학/졸업)는 사람에게, **멤버십**(활동중/OB)·**직책**(동아리장/부원)·**기수**는 사람×동아리마다 붙는다. 한 사람이 A 동아리에서는 12기 부원이고 B 동아리에서는 3기 동아리장일 수 있다.

로그인·회원가입·가입 신청·인원 목록은 별도 페이지가 아니라 네이티브 `<dialog>` 모달이다. ESC·포커스 트랩·스크롤 잠금을 브라우저가 처리해준다.

**비로그인도 목록과 공개 활동 글을 본다.** 신입생은 계정을 만들기 전에 동아리부터 보기 때문이다.

## AI 초안 흐름

![AI 초안 흐름도](docs/assets/ai-flow.svg)

이 기능의 핵심은 모델이 아니라 **무엇을 안 하게 만들었는가**다.

- **메모도 PDF도 없으면 초안을 만들지 않는다.** 사진만으로 쓰게 하면 AI는 "즐거운 시간을 보냈습니다" 같은 아무 동아리에나 붙는 문장을 지어낸다. 사실이 아닐 수도 있다.
- **사실은 메모와 PDF가 제공하고, 사진은 그 사실을 구체화하는 데만 쓴다.** "12명 참여"를 "12명이 필름 카메라를 들고" 정도로.
- **AI는 초안까지만.** 자동 게시는 없고, 게시된 글에 'AI 작성' 배지도 붙이지 않는다. 사람이 검수하고 고쳐서 자기 이름으로 올린 글이므로 저자는 사람이다.

키가 없어도 서비스는 정상 동작한다. 작성 화면은 그대로 열리고 'AI 초안 생성' 버튼만 비활성화된다. AI는 글쓰기를 **거드는** 기능이지 필수 경로가 아니다.

## 실행

### 전체 도커 (시연·최종 확인용)

```bash
cp .env.example .env
docker compose up --build              # 프론트 :8080 · API :8000
docker compose exec backend uv run --no-dev python seed.py
```

### 개발 모드 (Postgres만 도커)

```bash
docker compose up -d db

cd backend
uv sync
uv run python seed.py                   # 데모 데이터
uv run uvicorn app.main:app --reload    # :8000 · 문서 /api/docs

cd ../frontend
npm install
npm run dev                             # :5173 (API는 :8000 프록시)
```

### 데모 계정

| 역할 | 이메일 | 비밀번호 |
|---|---|---|
| 학생 | `26011234@mjc.ac.kr` | `test1234` |
| 동아리장 | `24010001@mjc.ac.kr` | `test1234` |
| 관리자 | `00000000@mjc.ac.kr` | `test1234` |

시드는 동아리 8개 · 활동 글 18건 · 심사중인 가입 신청 3건 · 개설 신청 1건을 넣는다. **시연 중 빈 화면이 나오지 않게 하기 위해서다.**

스키마를 바꿨으면 `docker compose down -v` 후 재생성 + `uv run python seed.py --reset`. 마이그레이션 도구는 쓰지 않는다(해커톤 한정).

### 검사

```bash
cd backend && uv run ruff check . && uv run pytest -q
cd frontend && npm run build
```

## 기술 선택과 이유

| 계층 | 선택 | 왜 |
|---|---|---|
| 백엔드 | FastAPI + SQLAlchemy 2 + psycopg | 타입 힌트가 그대로 문서(`/api/docs`)가 된다 |
| 프론트 | Vue 3 + Vite + Pinia | 목업이 순수 HTML/CSS/JS라 이식 비용이 가장 낮았다 |
| DB | PostgreSQL 16 | |
| 인증 | httpOnly 세션 쿠키 + bcrypt | JWT는 이 규모에서 이득이 없다. 로그아웃이 쿠키 삭제로 끝난다 |
| AI | 명지전문대 AI Gateway | 학교 인프라를 그대로 쓰고, 비용·사용량이 개인별로 분리된다 |
| PDF | pypdf 텍스트 추출 | 게이트웨이에 파일 업로드가 없어 서버가 먼저 글자를 뽑는다 |
| 마이그레이션 | **없음** — `create_all` + `seed.py` | 해커톤 한정. 스키마가 바뀌면 DB를 재생성한다 |

## 데이터 모델

10개 테이블. 전체 정의는 [`backend/app/models.py`](backend/app/models.py)에 있다.

| 테이블 | 역할 |
|---|---|
| `users` | **학번이 PK.** 이메일 도메인이 2종이라 학번을 키로 두면 중복 가입이 DB에서 막힌다 |
| `clubs` | 이름·분야·창립년도·모집 상태·현재 기수·운영 상태 |
| `club_members` | 사람×동아리 — 직책·멤버십·기수가 여기 붙는다 |
| `join_forms` · `join_requests` | 동아리장이 만든 가입폼과 신청 답변 |
| `leave_requests` | 탈퇴 요청. **7일 지나면 자동 승인** |
| `club_applications` | 개설 신청. 신규 창설과 기존 동아리 등록을 하나로 처리 |
| `posts` · `likes` | 활동 글(**공개 기본값 false**)과 좋아요 |
| `email_tokens` | 이메일 인증 |

## 의도적으로 뺀 것

기획 단계에서 빼기로 하고, 왜 뺐는지 함께 적었다.

| 뺀 것 | 이유 |
|---|---|
| 댓글 | 신고·삭제·분쟁 처리 구조가 따라붙는다. 이 서비스는 토론이 아니라 기록이 목적이다 |
| 동아리 정원 | 가입 승인과 모집 상태로 충분히 조절된다 |
| 사이트 내 알림함 | 이메일 + '내 신청 현황'으로 같은 목적을 달성한다 |
| AI 초안 다시 생성 · 문체 선택 | 직접 고치는 편이 빠르다 |
| 공용 AI 키 | 비용과 남용 책임이 한 곳에 몰린다 |
| 동아리 간 메시지·쪽지 | 학교 이메일과 단톡방이 이미 하고 있다 |

## 개인정보와 안전 원칙

1. **최소 노출** — 동아리장에게 보이는 신청자 정보는 이름·학과·**학년**뿐이다. 학번 전체는 이메일 주소와 같아 개인 식별 정보가 된다
2. **기본 비공개** — 활동 사진에는 학생 얼굴이 들어간다. 공개는 사람이 의식적으로 선택하는 행위여야 한다
3. **탈출구 보장** — 탈퇴는 7일 후 자동 처리된다. 동아리장이 잠수해도 사용자가 갇히지 않는다
4. **책임의 소재** — AI는 초안만 만든다. 게시된 글의 저자는 사람이다
5. **맡긴 자격증명은 돌려주지 않는다** — AI 키는 암호화 저장하고 조회는 불가능하다. 지우고 새로 넣는 것만 된다
